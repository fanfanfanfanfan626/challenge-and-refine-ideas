# Security policy

## Supported version

Security fixes are applied to the latest release and the `main` branch. The current stable release is listed in [`VERSION`](VERSION).

## Report a vulnerability

Use GitHub's private vulnerability-reporting feature for issues that could expose credentials, private prompts, user data, or unsafe execution paths. Do not post sensitive details in a public Issue.

For non-sensitive bugs, documentation problems, or installation questions, use the repository's Issue templates.

This package is an instruction workflow, not a security sandbox. Its professional-review and authorization gates reduce unsafe handoffs but do not replace host permissions, qualified review, or application security controls.
